# Single-Use Sticker Management

ระบบพิมพ์และติดตามสติ๊กเกอร์ Single-Use ขนาด 50 × 25 มม. สร้างด้วย Next.js, Ant Design และ TypeScript

## เริ่มใช้งาน

ต้องมี Node.js 20 ขึ้นไป

```bash
npm install
npm run dev        # โหมดพัฒนา  → http://localhost:3000
```

ใช้งานจริง:

```bash
npm run build
npm start          # → http://localhost:3000
```

## การตั้งค่าเครื่องพิมพ์

เครื่องพิมพ์หลัก: **Godex EZ120** (203 dpi = 8 จุด/มม., ต่อ USB)

### ตั้งค่าครั้งแรก (Godex EZ120)

1. ติดตั้งไดรเวอร์ GoDEX ของรุ่น EZ120 แล้วตั้งเป็นเครื่องพิมพ์หลัก (default)
2. ในคุณสมบัติไดรเวอร์ ตั้งขนาดกระดาษ **50 × 25 มม.** ชนิดสติ๊กเกอร์แบบมีช่องว่าง (gap)
3. ทำ calibrate เซนเซอร์กระดาษตามคู่มือเครื่อง (ทำซ้ำเมื่อเปลี่ยนม้วน)
4. ในโปรแกรม หน้า พิมพ์สติ๊กเกอร์ กดปุ่ม ⚙ **ตั้งค่าเครื่องพิมพ์** → **พิมพ์ทดสอบ**
   ถ้าข้อความไม่อยู่กลางกรอบสีส้ม ให้ปรับ **เลื่อนแนวนอน / แนวตั้ง** ทีละ 0.5 มม. แล้วพิมพ์ทดสอบซ้ำ
   (ค่าเก็บแยกตามเครื่อง ดวงทดสอบไม่ถูกบันทึกเป็นประวัติ)

บาร์โคดถูกปรับให้ 1 แท่งเล็กสุด = 2 จุดของหัวพิมพ์ 203 dpi (0.25 มม.) พอดีหัวพิมพ์ แท่งคม สแกนง่าย

### ล็อกให้พิมพ์ออกเครื่องเดียว (เช่น Pasin 2)

ดูขั้นตอนและไฟล์ที่ [`deploy/README.md`](deploy/README.md) — ทำตอนติดตั้งที่หน้างาน

### ทุกครั้งที่พิมพ์

1. กด **พิมพ์ทั้งหมด** แล้วหน้าต่างพิมพ์ของเบราว์เซอร์จะเปิดขึ้น
2. เลือกเครื่องพิมพ์ **Godex EZ120**
3. ขนาดกระดาษ **50 × 25 มม.** · Margins = **None** · Scale = **100%** (Chrome จำค่าไว้ให้ครั้งถัดไป)
4. ถ้าพิมพ์หลายดวง แต่ละดวงจะขึ้นหน้าใหม่ (ดวงถัดไปบนม้วน)

กรอบสีส้มพิมพ์มาจากโรงงานบนม้วนสติ๊กเกอร์ โปรแกรมพิมพ์เฉพาะเนื้อหาสีดำด้านใน

### ให้พิมพ์ออกทันทีโดยไม่ต้องกดยืนยันหน้าต่างพิมพ์

ตั้งเครื่องพิมพ์ฉลากเป็นเครื่องพิมพ์หลัก (default) แล้วเปิด Chrome ด้วย `--kiosk-printing` เช่น (macOS)

```bash
open -a "Google Chrome" --args --kiosk-printing http://localhost:3000/print
```

(Windows: เพิ่ม `--kiosk-printing` ต่อท้าย Target ของ shortcut Chrome)

## หน้า พิมพ์สติ๊กเกอร์

- ยิง SN ต่อเนื่องได้เรื่อย ๆ รายการจะสะสม แล้วกด **พิมพ์ทั้งหมด** ทีเดียว
- **วันผลิต** ตั้งแยกได้ทีละดวง ค่าเริ่มต้นคือวันนี้ (วันหมดอายุคำนวณตามรายการอุปกรณ์)
- พิมพ์รอบข้ามได้ แต่ต้องกรอกหมายเหตุ
- ต้อง **เลือกเจ้าหน้าที่ผู้พิมพ์** ก่อนพิมพ์ (ดรอปดาวน์ค้นหาชื่อ/รหัสได้) ชื่อจะพิมพ์บนสติ๊กเกอร์และบันทึกในประวัติ
  รายชื่อจัดการที่เมนู **รายชื่อเจ้าหน้าที่** (คนที่ลาออกให้ปิดใช้งาน — ลบได้เฉพาะคนที่ยังไม่เคยพิมพ์)
- มีเสียงตอบรับ: ปี๊บสั้น = ผ่าน, ปี๊บต่ำสองครั้ง = มีปัญหา (ไม่พบ SN / ครบรอบ / ยิงซ้ำ)
- รายการที่มีปัญหาค้างไว้พร้อมปุ่มแก้ (ลงทะเบียน / ทำลาย & เปลี่ยนชิ้น) และไม่ถูกพิมพ์

## ผู้ดูแลระบบ (แอดมิน)

- เจ้าหน้าที่ทั่วไปใช้ได้โดยไม่ต้องเข้าสู่ระบบ: พิมพ์สติ๊กเกอร์ · อุปกรณ์รายชิ้น · รายงาน
- เมนู **รายการอุปกรณ์ / รายชื่อเจ้าหน้าที่ / บัญชีแอดมิน** เห็นเฉพาะแอดมิน (กดปุ่ม **เข้าสู่ระบบแอดมิน** ล่างซ้าย)
- ไม่มีการสมัครเอง — บัญชีเริ่มต้น `admin` / `admin1234` (ควรเปลี่ยนรหัสผ่านที่เมนูบัญชีแอดมินก่อนใช้งานจริง)
- แอดมินที่เข้าสู่ระบบแล้วเพิ่มบัญชีอื่นได้ที่เมนูบัญชีแอดมิน
- ออกจากระบบอัตโนมัติเมื่อไม่ได้ใช้งาน 15 นาที หรือปิดแท็บ
- รหัสผ่านเก็บเป็น hash (PBKDF2-SHA256 + salt) ต้องเปิดผ่าน https:// หรือ localhost
- ข้อจำกัด: บัญชีเก็บในเบราว์เซอร์ของแต่ละเครื่อง (ไม่อยู่ในไฟล์สำรองข้อมูล) และเป็นการกันคนทั่วไปเข้าหน้าตั้งค่า
  ยังไม่ใช่ความปลอดภัยระดับเซิร์ฟเวอร์ — เมื่อย้ายไปฐานข้อมูลกลางควรย้ายการตรวจรหัสผ่านไปฝั่งเซิร์ฟเวอร์
- ลืมรหัสผ่านทุกบัญชี: ลบค่า `sticker_admins` และ `sticker_adminSeeded` ใน localStorage ของเครื่องนั้น แล้วรีโหลด จะได้บัญชี admin / admin1234 กลับมา

## ข้อมูล

- เก็บไว้ใน localStorage ของเบราว์เซอร์ **แยกตามเครื่องและเบราว์เซอร์**
- ควรกด **สำรองข้อมูล** ที่หน้าข้อมูลถาวรเป็นระยะ ไฟล์ JSON ที่ได้ใช้นำเข้าในเครื่องอื่นได้
- ถ้าภายหลังจะเปลี่ยนไปใช้ฐานข้อมูลจริง ให้เขียนคลาสใหม่ที่ implement `DataStorage` ใน `src/lib/storage.ts`
  แล้วเปลี่ยนตัวแปร `storage` จุดเดียว

## การติดตามอุปกรณ์รายชิ้น (SN)

อุปกรณ์แต่ละชิ้นมี SN ไม่ซ้ำกัน ระบบนับรอบแยกตามชิ้น

1. **ลงทะเบียน** — เลือกประเภท แล้วให้ระบบสร้าง SN (เช่น `SUC-000001`) หรือยิง SN จากผู้ผลิต
2. **พิมพ์สติ๊กเกอร์** — ยิง SN ของชิ้นที่ sterilize เสร็จ ระบบบันทึกรอบถัดไปและพิมพ์สติ๊กเกอร์
   (SN อยู่บนบาร์โคดของสติ๊กเกอร์)
3. **ครบรอบ** — เมื่อพิมพ์รอบสุดท้ายแล้ว (เช่น 4/4) ชิ้นนั้นจะพิมพ์ต่อไม่ได้ ยิงเข้ามาระบบจะแจ้งให้ทำลาย
4. **ทำลาย & ทดแทน** — บันทึกทำลาย (ครบรอบ / ชำรุด / สูญหาย / อื่น ๆ) แล้วลงทะเบียนชิ้นใหม่ทดแทน
   ระบบจะจำว่าชิ้นใหม่มาแทน SN ไหน

สถานะของแต่ละชิ้น: ชิ้นใหม่ → ใช้งานได้ → ครบรอบ รอทำลาย → ทำลายแล้ว

- รอบสูงสุดถูกบันทึกไว้กับแต่ละชิ้นตอนลงทะเบียน แก้ค่าที่ประเภทภายหลังจะมีผลกับชิ้นใหม่เท่านั้น
- พิมพ์ซ้ำ (สติ๊กเกอร์ชำรุด): ทำได้เฉพาะดวงล่าสุดของชิ้นที่ยังไม่ถูกทำลาย ใช้ SN วันที่ และรอบเดิม ไม่นับรอบเพิ่ม

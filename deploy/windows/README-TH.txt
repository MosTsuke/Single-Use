Single-Use Sticker - ชุดติดตั้งเครื่องแม่ (Windows 10/11 หรือ Windows Server 2016 ขึ้นไป แบบ 64-bit)
=====================================================================================

ภาพรวม
  - เครื่องแม่ 1 เครื่อง: รันโปรแกรม และเก็บข้อมูลใน SQL Server ที่มีอยู่ในเครื่อง
  - เครื่องอื่นในแลน: เปิด Chrome ไปที่ http://<IP เครื่องแม่>:3002 ไม่ต้องติดตั้งอะไรเพิ่ม
    (ยกเว้นเครื่องที่ต่อเครื่องพิมพ์สติ๊กเกอร์ ดูขั้นที่ 9)
  - ไม่ต้องต่ออินเทอร์เน็ต ไม่ต้องติดตั้ง Node.js (มีมาในชุดนี้แล้ว)
  - ไม่แตะฐานข้อมูลเดิมของโรงพยาบาล: สร้างฐานข้อมูลใหม่ชื่อ SingleUseSticker แยกต่างหาก
    พร้อม login singleuse_app ที่มีสิทธิ์เฉพาะฐานนี้ ไม่ต้อง restart SQL Server
    และโปรแกรมจะไม่ยอมเชื่อมต่อถ้าใส่ login ผู้ดูแลเซิร์ฟเวอร์ (เช่น sa)

สิ่งที่ต้องมีก่อนเริ่ม
  - สิทธิ์ admin ของเครื่องแม่
  - SSMS ที่เข้า SQL Server ได้ด้วย sa หรือ login ผู้ดูแล (sysadmin)
  - Google Chrome ในเครื่องที่จะพิมพ์สติ๊กเกอร์
  - วันที่และเวลาของเครื่องแม่ต้องถูกต้อง (เวลาในประวัติการพิมพ์มาจากเครื่องแม่)


ขั้นที่ 1  แตกไฟล์ zip
  - คลิกขวาไฟล์ zip > Extract All > เลือกปลายทางเป็น C:\
  - จะได้โฟลเดอร์ C:\singleuse-sticker (ถ้าเลือก C:\singleuse-sticker จะได้โฟลเดอร์ซ้อนกัน)
  - วางไดรฟ์อื่นได้ แต่ต้องเป็นที่ที่ไม่ถูกลบหรือย้าย

ขั้นที่ 2  เช็ค SQL Server (แค่อ่าน ไม่แก้อะไร)
  - เปิด SSMS > เข้าด้วย sa > กด New Query > วาง 2 บรรทัดนี้ แล้วกด Execute (F5)

      SELECT SERVERPROPERTY('IsIntegratedSecurityOnly') AS windows_auth_only, @@VERSION AS version;
      EXEC xp_readerrorlog 0, 1, N'Server is listening on';

  - windows_auth_only = 0 แปลว่าเปิดให้ login ด้วยรหัสผ่านได้แล้ว (ถ้าเป็น 1 ดู "ถ้ามีปัญหา" ข้อ 1)
  - ผลชุดที่สองต้องมีบรรทัด  Server is listening on [ 'any' <ipv4> 1433]
    เลขท้ายคือ port (ปกติ 1433) ถ้าเป็นเลขอื่นให้จดไว้ใช้ขั้นที่ 4
    บรรทัดที่เป็น 127.0.0.1 หรือ ::1 ไม่นับ / ถ้าไม่มีเลย ดู "ถ้ามีปัญหา" ข้อ 1
  - ถ้าเครื่องนี้ติดตั้ง Med Dashboard ไว้แล้ว สองอย่างนี้เปิดอยู่แล้ว ไปขั้นที่ 3 ได้เลย

ขั้นที่ 3  สร้างฐานข้อมูลใหม่ (ทำครั้งเดียว)
  - SSMS > File > Open > File... > เลือก C:\singleuse-sticker\database\00_create_database.sql
  - หาบรรทัด  DECLARE @AppPassword ... = N'CHANGE_ME_Str0ng!Pass';
    เปลี่ยน CHANGE_ME_Str0ng!Pass เป็นรหัสผ่านใหม่ (เก็บ N'...' ไว้)
      * ยาว 8 ตัวขึ้นไป มีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก และตัวเลข
      * ห้ามมีเครื่องหมาย  "  '  $  และช่องว่าง
  - กด Execute (F5) ด้านล่างต้องขึ้นว่า
      สร้างฐานข้อมูล SingleUseSticker แล้ว / สร้าง login singleuse_app แล้ว / เสร็จขั้นที่ 0
  - สคริปต์นี้สร้างแค่ฐานข้อมูลใหม่และ login ใหม่ ไม่แก้ฐานข้อมูลหรือ login อื่น
    ไม่ต้อง restart SQL Server โปรแกรมเดิมของโรงพยาบาลใช้งานได้ตามปกติ
  - ตารางในฐานข้อมูล โปรแกรมจะสร้างให้เองตอนเปิดครั้งแรก (ไม่ต้องรันไฟล์ 01_ 02_ 03_)
  - จดรหัสผ่านไว้ ใช้ในขั้นที่ 4

ขั้นที่ 4  ตั้งค่าการเชื่อมต่อ
  - ดับเบิลคลิก 1-start.bat ครั้งแรก จะเปิดไฟล์ singleuse.env ใน Notepad ให้
  - บรรทัด DB_PASSWORD="CHANGE_ME" ให้แทน CHANGE_ME ด้วยรหัสผ่านจากขั้นที่ 3 (เก็บเครื่องหมายคำพูดไว้)
  - ถ้าขั้นที่ 2 เห็น port ไม่ใช่ 1433 ให้แก้ DB_PORT เป็นเลขนั้น
  - กดบันทึก แล้วปิด Notepad

ขั้นที่ 5  เปิดครั้งแรก: สร้างบัญชีแอดมิน และใส่โลโก้โรงพยาบาล
  - ดับเบิลคลิก 1-start.bat อีกครั้ง จะมีหน้าต่างสีดำ
  - ครั้งแรกจะขึ้น "กำลังติดตั้งโครงสร้างฐานข้อมูล 01_... 02_... 03_..." แล้วตามด้วย
    "เชื่อมต่อฐานข้อมูล SingleUseSticker แล้ว — พร้อมใช้งาน"
    (ถ้าขึ้นข้อความอื่น ดู "ถ้ามีปัญหา")
  - ถ้า Windows ถามเรื่อง firewall ให้กด Allow access (อย่ากด Cancel)
  - เปิด Chrome ไปที่ http://localhost:3002 จะขึ้นหน้า "ตั้งค่าครั้งแรก" 2 ขั้น ต้องทำให้ครบก่อนใช้งาน
      1) บัญชีแอดมิน: กรอกชื่อผู้ใช้และรหัสผ่าน แล้วกด "สร้างบัญชีและไปขั้นถัดไป"
         (ไม่มีรหัสผ่านเริ่มต้น — จดชื่อผู้ใช้และรหัสผ่านเก็บไว้ ใช้เข้าเมนูผู้ดูแลระบบ)
      2) โลโก้และชื่อโรงพยาบาล: เลือกรูปโลโก้ (PNG / SVG / JPG) กรอกชื่อโรงพยาบาล แล้วกด "บันทึกและเริ่มใช้งาน"
         (เตรียมไฟล์โลโก้ไปด้วย — แนะนำรูปสี่เหลี่ยมจัตุรัส พื้นหลังโปร่งใส)
  - ตรวจ: เปิด http://localhost:3002/api/health ต้องขึ้น "ok":true

ขั้นที่ 6  ส่งต่อให้หน้างานกรอกข้อมูลเอง
  - ฐานข้อมูลเริ่มต้นว่าง (ไม่มีข้อมูลตัวอย่าง) มีแค่บัญชีแอดมินกับโลโก้จากขั้นที่ 5
  - หน้างานเข้าสู่ระบบแอดมิน (ปุ่มล่างซ้าย) แล้วเพิ่มข้อมูลจริงเองที่เมนูผู้ดูแลระบบ:
      รายการอุปกรณ์ (ชื่อ อายุหลัง sterilize รอบสูงสุด คำนำหน้า SN) / รายชื่อเจ้าหน้าที่ / หน่วยงาน (ถ้าใช้ "ใช้ที่")
      และเพิ่มบัญชีแอดมินอื่นได้ที่เมนู บัญชีแอดมิน
  - ลงทะเบียนอุปกรณ์รายชิ้น: เมนู อุปกรณ์รายชิ้น > ลงทะเบียน หรือยิง SN ที่หน้าพิมพ์สติ๊กเกอร์
  - ข้อมูลเยอะ กรอกทีละชุดได้: ทุกเมนูข้างบนมีปุ่ม "ไฟล์ต้นแบบ" (ดาวน์โหลด CSV ไปกรอกใน Excel)
    และ "นำเข้า CSV" (ตรวจทุกแถวและแสดงตัวอย่างก่อนบันทึก ถ้ามีแถวผิดจะไม่บันทึกเลย ให้แก้ไฟล์แล้วนำเข้าใหม่)
    ตอนบันทึกจาก Excel เลือกชนิดไฟล์ "CSV UTF-8" หรือ "CSV (Comma delimited)" ก็ได้
  - ปิดหน้าต่างสีดำได้ (โปรแกรมจะหยุด) แล้วทำขั้นที่ 7 ต่อ

ขั้นที่ 7  ให้เปิดเองทุกครั้งที่เปิดเครื่อง
  - คลิกขวา 2-install-autostart.bat > Run as administrator
  - ไม่ต้อง login เข้า Windows ก็ทำงาน และถ้าหยุดทำงานจะเปิดใหม่เองภายใน 1 นาที
  - บันทึกการทำงานอยู่ที่ logs\server.log

ขั้นที่ 8  ให้เครื่องอื่นในแลนเปิดได้
  - คลิกขวา 3-open-firewall.bat > Run as administrator
  - หน้าต่างจะบอก IP ของเครื่องแม่ (เช่น 192.168.1.10) จดไว้
  - เครื่องอื่นเปิด Chrome ไปที่ http://192.168.1.10:3002 (ใช้ IP จริง)
  - เปิดให้เฉพาะเครื่องในวงแลนเดียวกันเท่านั้น
  - ควรให้ฝ่าย IT ล็อก IP ของเครื่องแม่ (static IP หรือจองใน DHCP)
    ไม่งั้นถ้า IP เปลี่ยน เครื่องอื่นจะเปิดไม่ได้จนกว่าจะแก้ที่อยู่ใหม่

ขั้นที่ 9  ตั้งเครื่องที่พิมพ์สติ๊กเกอร์ (ทุกเครื่องที่ต่อเครื่องพิมพ์ Godex EZ120 รวมเครื่องแม่ถ้าต่อไว้)
  1. ติดตั้งไดรเวอร์ Godex EZ120 ตั้งชื่อเครื่องพิมพ์ใน Windows ว่า  Pasin 2
     ตั้งกระดาษในไดรเวอร์ 50 x 25 มม. ชนิดมีช่องว่าง (gap) และ calibrate เซนเซอร์ตามคู่มือเครื่อง
  2. copy โฟลเดอร์ client ไปไว้ในเครื่องนั้น (เครื่องแม่ใช้ในโฟลเดอร์นี้ได้เลย)
  3. ถ้าชื่อเครื่องพิมพ์ไม่ใช่ Pasin 2: เปิด client\1-set-printer-Pasin2.reg ด้วย Notepad
     แก้ชื่อหลัง namePattern ให้ตรงทุกตัวอักษร แล้วบันทึก
  4. ดับเบิลคลิก client\1-set-printer-Pasin2.reg (ต้องใช้สิทธิ์ admin) — Chrome จะเลือกเครื่องพิมพ์นี้เอง
  5. เปิด client\Single-Use.bat ด้วย Notepad แก้บรรทัด APP_URL
       - เครื่องแม่: ใช้ http://localhost:3002/print ได้เลย
       - เครื่องอื่น: เปลี่ยน localhost เป็น IP จากขั้นที่ 8 เช่น http://192.168.1.10:3002/print
  6. สร้าง shortcut ของ Single-Use.bat ไว้บน Desktop ให้เจ้าหน้าที่เปิดโปรแกรมจากตรงนี้เท่านั้น
     (กดพิมพ์แล้วสติ๊กเกอร์ออกทันที ไม่มีหน้าต่างให้เลือกเครื่องพิมพ์)
  7. เปิดโปรแกรม > หน้าพิมพ์สติ๊กเกอร์ > ปุ่มเฟือง (ตั้งค่าเครื่องพิมพ์) > พิมพ์ทดสอบ
     ถ้าข้อความไม่อยู่กลางกรอบสีส้ม ปรับเลื่อนแนวนอน/แนวตั้งทีละ 0.5 มม. แล้วพิมพ์ทดสอบซ้ำ
     (ค่านี้เก็บแยกในแต่ละเครื่อง)

ขั้นที่ 10  ตั้งเครื่องแม่ไม่ให้ sleep
  - Settings > System > Power > Screen and sleep
  - "When plugged in, put my device to sleep after" = Never
  - ถ้าเครื่องแม่ sleep หรือปิดอยู่ ทุกเครื่องจะใช้โปรแกรมไม่ได้


ตรวจสอบก่อนส่งมอบ
  [ ] http://localhost:3002/api/health ขึ้น "ok":true
  [ ] เครื่องอื่นในแลนเปิด http://<IP เครื่องแม่>:3002 ได้
  [ ] เครื่องที่พิมพ์: ยิง SN ทดสอบ พิมพ์ออกตรงกรอบ แล้วกด "ไม่ได้พิมพ์ – ย้อนกลับ" (ไม่นับรอบ)
  [ ] รีสตาร์ทเครื่องแม่ 1 ครั้ง แล้วเครื่องอื่นเปิดโปรแกรมได้เองโดยไม่ต้อง login เข้า Windows
  [ ] ทำครบทุกเครื่องแล้ว ทุกเครื่องเห็นข้อมูลชุดเดียวกัน (พิมพ์จากเครื่องหนึ่ง อีกเครื่องเห็นภายในไม่กี่วินาที)


การสำรองข้อมูล
  - โปรแกรมสำรองฐานข้อมูล SingleUseSticker ให้เองวันละครั้ง เก็บ 7 ไฟล์วนตามวันในสัปดาห์
    ชื่อ SingleUseSticker_Mon.bak ... SingleUseSticker_Sun.bak ในโฟลเดอร์ Backup ของ SQL Server
    ดูว่าโฟลเดอร์อยู่ไหน: SSMS รัน  SELECT SERVERPROPERTY('InstanceDefaultBackupPath')
  - ควร copy ไฟล์เหล่านี้ไปเก็บนอกเครื่องเป็นระยะ (NAS / ฮาร์ดดิสก์ภายนอก)
    เพราะถ้าดิสก์เครื่องแม่เสีย ไฟล์สำรองในเครื่องก็หายไปด้วย
  - ถ้าฝ่าย IT มีแผนสำรองข้อมูลของ SQL Server อยู่แล้ว ให้เพิ่มฐาน SingleUseSticker เข้าไปด้วย
    (การสำรองของโปรแกรมเป็นแบบ COPY_ONLY ไม่กระทบแผนเดิม)
  - กู้คืน: SSMS > คลิกขวา Databases > Restore Database... เลือกไฟล์ .bak (ให้ฝ่าย IT ทำ
    และหยุดโปรแกรมก่อนด้วย stop.bat)


อัปเดตรุ่นใหม่
  1. วางไฟล์ zip รุ่นใหม่ (singleuse-sticker-windows-....zip) ไว้ในโฟลเดอร์นี้ ไม่ต้องแตก
  2. คลิกขวา 4-update.bat > Run as administrator แล้วรอจนขึ้นว่า "อัปเดตเรียบร้อย"
  - สคริปต์จะหยุดโปรแกรม ใส่รุ่นใหม่ เปิดกลับ แล้วลบไฟล์ zip ให้เอง
  - ถ้ารุ่นใหม่ต้องเพิ่มตารางหรือคอลัมน์ โปรแกรมจะอัปเดตฐานข้อมูลให้เองตอนเปิด (ข้อมูลเดิมอยู่ครบ)
  - singleuse.env (รหัสผ่าน) โฟลเดอร์ logs และ client ไม่ถูกแตะ
  - ถ้าใส่รุ่นใหม่ไม่สำเร็จ จะคืนรุ่นเดิมและเปิดกลับให้เอง


ถอนการติดตั้ง
  1. คลิกขวา uninstall.bat > Run as administrator
  2. ลบโฟลเดอร์นี้ทิ้ง
  3. ฐานข้อมูลยังอยู่ใน SQL Server ครบ ถ้าเลิกใช้ถาวรและต้องการลบข้อมูลทิ้งด้วย
     (สำรองก่อน — ลบแล้วกู้คืนไม่ได้) SSMS รัน:
       DROP DATABASE SingleUseSticker;
       DROP LOGIN singleuse_app;


ถ้ามีปัญหา
  1. ขั้นที่ 2 พบว่ายังไม่เปิด SQL Server Authentication (windows_auth_only = 1) หรือ TCP/IP
     ต้องแก้ค่าที่ SQL Server แล้ว restart service ซึ่งทำให้โปรแกรมเดิมที่ใช้ SQL Server ตัวนี้
     หยุดชั่วครู่ — ตกลงกับผู้ดูแลระบบเดิมก่อน และทำนอกเวลางานเท่านั้น
       - SSMS > คลิกขวาที่ server > Properties > Security > "SQL Server and Windows Authentication mode"
         (login แบบ Windows เดิมยังใช้ได้ตามปกติ)
       - SQL Server Configuration Manager > SQL Server Network Configuration > Protocols for ...
         > TCP/IP = Enabled (ไม่ต้องเปลี่ยน port)
       - restart service "SQL Server (...)" ครั้งเดียว แล้วเช็คว่าโปรแกรมเดิมใช้งานได้ปกติ
  2. หน้าเว็บหรือหน้าต่างดำขึ้นว่า "เข้าสู่ฐานข้อมูลไม่สำเร็จ"
     รหัสผ่านใน singleuse.env ไม่ตรงกับขั้นที่ 3 หรือยังไม่ได้รัน 00_create_database.sql
  3. "เชื่อมต่อ SQL Server ไม่ได้"
     SQL Server ไม่ได้เปิด หรือ port ไม่ตรง (ดูขั้นที่ 2 แล้วแก้ DB_PORT)
     ถ้า SQL Server เป็น instance ที่มีชื่อ (เช่น SQLEXPRESS) ใช้ DB_INSTANCE แทน DB_PORT ได้ (ดูใน singleuse.env)
  4. ข้อความเกี่ยวกับ TLS / SSL / certificate
     แก้ DB_ENCRYPT=true เป็น DB_ENCRYPT=false ใน singleuse.env แล้วเปิดโปรแกรมใหม่
  5. "login ที่ตั้งไว้เป็นผู้ดูแลทั้งเซิร์ฟเวอร์ (sysadmin)"
     ใน singleuse.env ต้องใช้ DB_USER=singleuse_app เท่านั้น ห้ามใช้ sa
  6. port 3002 ถูกโปรแกรมอื่นใช้อยู่ (หน้าต่างดำขึ้น EADDRINUSE)
     แก้ PORT ใน singleuse.env เป็นเลขอื่น เช่น 3005 แล้วรัน 3-open-firewall.bat ใหม่
     และแก้เลข port ใน APP_URL ของ Single-Use.bat ทุกเครื่อง
  7. เครื่องอื่นเปิดไม่ได้ แต่เครื่องแม่เปิดได้
     ยังไม่ได้ทำขั้นที่ 8 / IP เครื่องแม่เปลี่ยน / อยู่คนละวงแลน (ลอง ping IP เครื่องแม่)
  8. หน้าเว็บขึ้นแถบแดง "เชื่อมต่อฐานข้อมูลที่เครื่องแม่ไม่ได้"
     เครื่องแม่ปิด / sleep / สายแลนหลุด — เปิดเครื่องแม่แล้วรอ 1 นาที หน้าเว็บจะกลับมาเอง
  9. ลืมรหัสผ่านแอดมินทุกบัญชี
     SSMS รัน (ลบเฉพาะบัญชีแอดมิน ข้อมูลอื่นไม่หาย):
       USE SingleUseSticker;
       UPDATE dbo.Settings SET UpdatedByAdminId = NULL;
       DELETE FROM dbo.AdminAccounts;
     แล้วเปิดหน้าเว็บใหม่ จะขึ้นหน้าสร้างบัญชีแอดมินแรกอีกครั้ง
  10. ปัญหาอื่น ๆ: แคปหน้าจอ และส่งไฟล์ logs\server.log ให้ผู้พัฒนา
